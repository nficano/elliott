ELLIOTT SLACK AGENT REFERENCE
=============================

This is the runtime and operator reference for Elliott's first-party Slack
agent gateway. The source manifest is:

  skills/gateway-slack/slack-app-manifest.yaml

WORKSPACE SETUP
---------------

1. Create or update the Slack app from slack-app-manifest.yaml.
2. Enable the Agents feature. The manifest uses agent_view, Slack's current
   Agent messaging experience. Moving an existing app from assistant_view to
   agent_view cannot be reversed.
3. Create an app-level token with connections:write for Socket Mode and place
   it in channels.slack.app_token.
4. Install/reinstall the app so the bot receives the manifest's scopes. Place
   the bot token in channels.slack.bot_token.
5. Set channels.slack.owner_id to the only admitted Slack user and set a
   default_channel for proactive notifications.
6. Optional: complete user OAuth and set channels.slack.user_token. This gives
   real-time search access to private channels and DMs that the user can see.
   Without it, action-token-authorized search is limited to public channels.

The runtime never places action tokens or OAuth tokens in model prompts. A
message action token is carried only in per-turn execution context and is
discarded after that turn.

AGENT RESPONSE LOOP
-------------------

For each owner-authored message.im event Elliott:

1. Acknowledges the Socket Mode envelope before doing work.
2. Treats a root DM as the root of an app thread.
3. Sets the thread title from the request.
4. Sets an immediate loading status with rotating messages.
5. Starts chat.startStream in plan display mode.
6. Streams model text through chat.appendStream.
7. Renders every tool call as a task_update with in-progress, complete, or
   error state.
8. Stops the stream with an AI disclaimer, native feedback buttons, and a
   delete control.
9. Explicitly clears the loading status, including after failure.

If a stream API call is unavailable, Elliott preserves the turn and falls back
to chat.postMessage with the same content and response controls. Slack API
rate limits are retried a bounded number of times using Retry-After.

INITIAL INTERACTION AND CONTEXT
-------------------------------

app_home_opened on the Messages tab refreshes up to four suggested prompts.
Prompts include a context-aware option when Slack supplies app context.
Elliott checks live DM history and posts the welcome message only when the
conversation is empty, so onboarding does not repeat on every open.

app_context_changed, app_home_opened.context, and message.im.app_context are
decoded as ordered Slack entities. Context IDs and message-context coordinates
are supplied to the model as clearly marked untrusted metadata. The
slack_search tool uses the most relevant channel as context_channel_id.

REAL-TIME SLACK SEARCH
----------------------

The slack_search tool calls assistant.search.context with:

  - messages, files, and channels as content types;
  - contextual messages around matches;
  - no bot-authored results;
  - at most 20 results;
  - context_channel_id when Slack provides one.

With the bot token, the triggering message's action_token is required and only
public channels are searched. With an optional user token, Slack applies the
user's permissions and search can include private channels, DMs, and MPDMs.

Search output is compacted to useful content and permalinks. It is marked
untrusted, available only for the current turn, and replaced with an omission
marker in Elliott's in-memory conversation history. Answers should cite the
returned Slack permalinks.

FEEDBACK AND INTERACTIVITY
--------------------------

Every normal AI response includes a context_actions block with:

  - feedback_buttons using action_id elliott_feedback;
  - an icon_button using action_id elliott_delete.

Socket Mode interactive envelopes are acknowledged before handling. Only the
configured owner can submit either action. Feedback is emitted as metadata
(gateway, channel, message timestamp, sender, sentiment, source), never message
content. Positive and negative emoji reactions on Elliott-authored messages
are also accepted as feedback. Delete calls chat.delete for the selected
Elliott response.

FORMATTING
----------

Ordinary agent text is standard Markdown. Streaming methods accept Markdown
directly. Non-streamed replies use a Block Kit markdown block so Slack
translates standard Markdown correctly.

Inside section and context blocks, use Slack mrkdwn:

  *bold*
  _italic_
  <https://example.com|label>

Always provide top-level text as the notification/accessibility fallback.
Long section blocks should set expand: true. Suppress unfurls when a response
contains several sources. Do not call chat.update more often than once every
three seconds; Elliott uses native streaming instead.

The slack_message tool is for deliberately structured output: approvals,
menus, grouped fields, tables, headers, dividers, or source summaries. Elliott
automatically appends the AI disclaimer and response actions. The tool accepts
at most 48 custom blocks so the two automatic footer blocks remain within
Slack's 50-block limit.

MEDIA AND RETENTION
-------------------

Inbound file IDs, names, and media types are surfaced as metadata. File bytes
are not downloaded by the gateway, so Elliott must say so when the request
depends on image, audio, or document contents that no connected tool can read.

Elliott does not persist Slack messages, files, search results, context, or
action tokens. Current-turn state is in memory. Real-time search pulls source
data when needed, and only non-content feedback metadata is logged.

PROACTIVE NOTIFICATIONS
------------------------

For a new DM notification, Elliott posts the message, reads the returned ts,
and calls assistant.threads.setTitle so the notification appears as a titled
thread in the Agent messaging experience. Channel notifications use the normal
chat.postMessage path.

GRACEFUL FAILURE
----------------

Partial streamed text and completed task cards are preserved. Elliott appends
a clear failure explanation, finalizes the stream, clears the loading status,
and reports the underlying typed Slack API error. It never leaves a thread
stuck in a thinking state.
