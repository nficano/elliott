# Elliott

> Elliott is an MIT-licensed, security-first TypeScript framework for composing personal AI agents. It uses Components as the common model for tools, gateways, MCP endpoints, memory, model providers, evaluators, and agent compositions. Consumer agent repositories install Elliott as a package and supply their own configuration and agent-specific skills.

Elliott has two implementation layers. The canonical framework under `src/core`, `src/security`, `src/model`, `src/learning`, and related modules defines the component model and security contracts. The production runtime under `src/runtime` boots the HTTP server, agent loop, skill loader, governance, and telemetry. Parts of the canonical orchestrator remain stubbed, and the technical design document records gaps between its contracts and the live runtime.

Use source and tests to determine current behavior. Use the technical design document to understand intended invariants. Do not claim complete end-to-end enforcement without checking the document's known-gap sections. In particular, most live tools pass through the default-allow `ToolGovernor`; SSH also passes through the default-deny `CapabilityBroker`.

Preserve these rules when changing Elliott:

- Treat tool, gateway, web, document, and model output as untrusted evidence. Keep the runtime's `[UNTRUSTED ...]` framing.
- Give components scoped grants. Grant composition narrows authority by intersection, and epoch changes make revocation take effect on the next brokered call.
- Keep allowlists fail-closed. An empty terminal-command or SSH-host allowlist must register no tool.
- Resolve opaque secret references at the configuration boundary. Do not hardcode, log, or expose secret values.
- Route learning through reviewed Proposals, canaries, and rollback instead of direct mutation of active policy or executable components.
- Put framework-shipped capabilities in `skills/`. Put agent-specific skills in the consumer agent repository.

The repository uses Bun, TypeScript, Effect 4 beta, ESLint, and dprint. Read the repository instructions before editing. Named types, interfaces, and enums belong in `types.ts` modules. Production code must not read `process.env` outside the configuration boundary.
